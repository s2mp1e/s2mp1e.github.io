# 车规认证流程 / Automotive Qualification Flow

---

## 一、Qualification 全流程

```
车规芯片认证总流程:

┌──────────────────────────────────────────┐
│ ① 产品定义 (车规需求)                      │
│    Grade 确定 / 车厂要求收集                │
├──────────────────────────────────────────┤
│ ② 设计阶段 (DFR)                          │
│    可靠性设计 (Design for Reliability)     │
│    ESD/LU 设计 / 冗余设计                   │
├──────────────────────────────────────────┤
│ ③ 晶圆/封装 (车规工艺)                      │
│    IATF 16949 认证工厂                     │
├──────────────────────────────────────────┤
│ ④ AEC-Q100 测试 (Qualification)           │
│    3 批次样本 → 全部测试组                  │
│    3~6 个月周期                            │
├──────────────────────────────────────────┤
│ ⑤ PPAP 文档提交                            │
│    全套文档 → 车厂审核                      │
├──────────────────────────────────────────┤
│ ⑥ 车厂批准 (Approval)                      │
│    进入 AVL (合格供应商清单)                │
├──────────────────────────────────────────┤
│ ⑦ 量产 + 持续可靠性监控                     │
│    定期 HTOL/TC/HAST + PAT + BI           │
└──────────────────────────────────────────┘
```

## 二、Qualification 计划

### 2.1 测试矩阵 (Test Matrix)

```
示例: PMIC Grade 1 的 Qual 计划

| 测试组 | 测试项 | 条件 | 样本 | 周期 |
|--------|--------|------|------|------|
| A | TC | -55/125°C × 1000c | 77×3 | 10 周 |
| A | HTSL | 150°C × 1000h | 77×3 | 8 周 |
| A | HAST | 130°C/85% × 96h | 77×3 | 2 周 |
| A | THB | 85°C/85% × 1000h | 77×3 | 8 周 |
| B | HTOL | 125°C × 1000h | 77×3 | 8 周 |
| B | ELFR | 125°C × 48h | 800 | 1 周 |
| C | WBS/WBP | — | 10×3 | 1 周 |
| E | HBM | 2kV 目标 | 3×3 | 2 周 |
| E | CDM | 500V 目标 | 3×3 | 2 周 |
| E | LU | 125°C, 100mA | 3×3 | 1 周 |
| F | PAT | 全参数 | 全批 | 持续 |
```

### 2.2 时间线

```
典型 Qual 时间线 (并行执行):

月 1:  样本准备 + 初始电测
月 2:  应力测试启动 (TC/HTOL/HTSL/HAST 并行)
月 3:  短周期测试完成 (HAST/ELFR/ESD)
月 4:  中周期测试完成 (部分)
月 5:  长周期测试完成 (TC 1000c/HTOL 1000h)
月 6:  最终电测 + 数据分析 + 报告
月 7:  PPAP 提交
月 8:  车厂批准
```

## 三、PPAP (Production Part Approval Process)

### 3.1 PPAP 文档包

```
PPAP (生产件批准程序) 需要提交的文档:

① 设计记录 (Design Record)
② 工程变更文件 (ECN, 如有)
③ 客户工程批准 (如要求)
④ DFMEA (设计失效模式分析)
⑤ 工艺流程图 (Process Flow Diagram)
⑥ PFMEA (过程失效模式分析)
⑦ 控制计划 (Control Plan)
⑧ MSA (测量系统分析) — 含 GR&R
⑨ 尺寸结果 (Dimensional Results)
⑩ 材料/性能测试记录 (含 AEC-Q100 报告)
⑪ 初始过程研究 (SPC/Cpk 数据)
⑫ 合格实验室文件
⑬ 外观批准报告 (AAR)
⑭ 样品产品 (Sample Parts)
⑮ 标准样品 (Master Sample)
⑯ 检查辅具
⑰ 客户特殊要求
⑱ PSW (零件提交保证书) ← 核心文件
```

### 3.2 ATE 相关的 PPAP 要求

```
ATE 测试在 PPAP 中的角色:

① 控制计划中的测试项定义
② GR&R 数据 (测试系统重复性)
③ Cpk 数据 (关键参数过程能力)
④ 测试程序版本管理
⑤ 校准记录
```

## 四、变更管理 (Change Management)

### 4.1 车规变更的严格性

```
任何变更都需要重新验证:

变更类型 → 重新 Qual 范围:

① 设计变更 (金属层改版)
   → 全 AEC-Q100 重测

② 工艺变更 (代工厂迁移)
   → 全 AEC-Q100 重测

③ 封装变更 (封装厂/材料)
   → Group A/C/G 重测

④ 测试变更 (程序/Limit 修改)
   → 相关性验证 (Correlation)
   → 车厂批准

⑤ 测试厂迁移
   → Correlation + GR&R
```

### 4.2 PCN (Product Change Notice)

```
变更通知流程:

芯片厂发现变更需求
    ↓
内部评估 → 制定重新 Qual 计划
    ↓
向车厂发出 PCN (提前 6 个月, 典型)
    ↓
车厂评估 → 批准/拒绝/要求更多数据
    ↓
执行变更 + 重新 Qual
    ↓
提交 PPAP 更新
```

## 五、持续可靠性监控

```
量产阶段的持续监控项目:

每季度:
  HTOL (45~77 颗)
  HAST (45~77 颗)
  ESD 抽测

每半年:
  TC (77 颗)
  HTSL (77 颗)

持续:
  PAT (100%)
  BI 数据监控
  良率 SBA
  客户失效分析 (8D 报告)

数据流向:
  监控数据 → 趋势分析 → 异常预警 → 改善措施
```
