# V93000：Capture 与 Pattern 的关系及 Pattern 创建

**分类：** 数字采集 / Pattern 开发  
**状态：** 待核实  
**来源：** 用户提供的对话资料；未提供项目 Pattern 和 SmarTest 版本

## 现象

需要采集 DUT 的数字响应，但不清楚采集动作是否由 Pattern 定义、是否需要自行创建 Pattern，以及代码如何执行该 Pattern。

## 条件

- 接口协议、引脚和时序：资料未提供
- SmarTest 版本、Pattern 格式和调用代码：资料未提供

## 排查与发现

1. 先明确要采集的信号、有效时刻、采集长度和后续判定方式。
2. 检查项目 Pattern 是否已经包含对应的响应采集或比较行为；不同测试流程可能使用不同 Pattern、工具生成数据或其他测量资源。
3. 沿测试流程追踪 Pattern / Burst 的绑定与执行位置，再确认采集结果如何保存和读取。
4. 通过 Pattern 编译、项目范例及 TDC 确认实际语法。不要直接把对话中的 `C` 符号或示例 API 当成所有项目通用语法。
5. 用已知响应或可控 DUT 验证采样时序、返回数据和结果长度。

## 原因与处理

- **当前理解：** 数字响应的采样时刻通常需要由测试配置或测试数据明确规定；标签本身不能代替采样时序定义。
- **待核实：** 具体项目是否必须新建 Pattern，或可复用已有 Pattern / 生成工具，需检查工程结构和版本文档。
- **建议处理：** 优先复用经过验证的项目范例；确需新增时，独立验证 Pattern、时序和采集结果。

## 经验

先确认采样行为在哪里定义，再确认结果标签在哪里命名。Pattern 执行、采样配置和软件结果读取是相关但不同的环节。
