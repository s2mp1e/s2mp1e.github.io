## 1. 管脚 OS 测试 (Open/Short Test)

### 1.1 测试目的

管脚 OS (Open/Short) 测试，也称为 **Contact Test** 或 **Continuity Test**，是 FT 测试中**第一个执行**的测试项。其目的是：

- 验证 DUT 所有管脚与测试板（DUT Board / Load Board）之间是否建立了良好的电气接触
- 检测是否存在焊接开路（Open）、相邻管脚短路（Short）或管脚与电源/地短路等封装缺陷
- 避免因接触不良导致后续测试项误判（False Fail / False Pass）

### 1.2 测试原理

OS 测试利用芯片每个 I/O 管脚上**固有的 ESD 保护二极管结构**（即 P 阱到 GND 和 N 阱到 VDD 的寄生二极管）进行测试：

- **到 GND 的二极管**：向 GND 方向（从管脚到 GND）的正向压降，通常约为 0.5V ~ 0.8V
- **到 VDD 的二极管**：向 VDD 方向（从管脚到 VDD）的正向压降，通常约为 0.5V ~ 0.8V

由于在 FT 阶段芯片尚未上电（VDD = 0V），当对一个管脚施加正向电流时，电流会通过 ESD 二极管流向 GND，产生一个稳定的二极管正向压降。通过测量该压降，可以判断管脚是否正常连接。

### 1.3 测试方法

#### 方法一：Force Current — Measure Voltage (FIMV)

使用 PPMU 或 SMU 对每个管脚施加一个正向电流（通常为 +100µA ~ +1mA），然后测量管脚对 GND 的电压。

- **正常连接**：测得 Vpin ≈ +0.5V ~ +0.8V（二极管正向压降）
- **开路（Open）**：测得 Vpin 接近 0V（电荷泄放）或浮空值
- **短路到 GND**：测得 Vpin ≈ 0V
- **短路到 VDD**：测得 Vpin 接近二极管反向或异常高值

#### 方法二：Force Voltage — Measure Current (FVMI)

对每个管脚施加一个固定电压（如 +0.5V），然后测量流过管脚的电流。

- **正常连接**：测得 Ipin 在预期范围内（如 µA 级）
- **开路（Open）**：测得 Ipin ≈ 0A
- **短路到 GND**：测得 Ipin 异常大

#### ATE 测试伪代码示例

```csharp
// 管脚 OS 测试 — 使用 FIMV 方法
// Setup: 所有电源管脚 GND = 0V, VDD 浮空
void OS_Test()
{
    double  I_force = +500e-6;    // 500µA 正向电流
    double  V_os_lo = 0.2;        // 下限: 200mV
    double  V_os_hi = 1.0;        // 上限: 1000mV
    double  v_measured;

    for each (pin in AllPins)
    {
        // PPMU 配置: Force Current, Measure Voltage
        PPMU_ForceCurrent(pin, I_force);
        PPMU_MeasureVoltage(pin, out v_measured);

        // 判定
        if (v_measured >= V_os_lo && v_measured <= V_os_hi)
            TestResult_Pass(pin);
        else
            TestResult_Fail(pin, "OS_FAIL", v_measured);
    }
}
```

### 1.4 测试条件

| 参数               | 规格             | 说明                 |
| ---------------- | -------------- | ------------------ |
| 强制电流 (I_force)   | +100µA ~ +1mA  | 视管脚类型而定，电源管脚可用较大电流 |
| 测量电压上限 (V_os_hi) | 0.8V ~ 1.2V    | 根据 ESD 二极管特性设定     |
| 测量电压下限 (V_os_lo) | 0.1V ~ 0.3V    | 排除短路到 GND 的情况      |
| 温度               | 常温 (25°C)      | OS 测试通常在常温进行       |
| DUT 供电状态         | VDD = 0V (未上电) | 所有电源轨必须保持 0V       |

### 1.5 判定标准

| 状态 | 测量值 | 判定 |
|------|--------|------|
| 正常连接 | 0.3V < Vpin < 0.8V | PASS |
| 开路 (Open) | Vpin ≈ 0V 或浮空 | FAIL — Open |
| 短路到 GND | Vpin ≈ 0V | FAIL — Short-to-GND |
| 短路到 VDD | Vpin > 1.2V 或 < 0V | FAIL — Short-to-VDD |
| 相邻管脚短路 | Vpin 异常 (偏移) | FAIL — Bridge Short |

### 1.6 注意事项

1. **测试顺序**：OS 测试必须是 FT 测试流程中的**第一个测试项**，必须在芯片上电之前完成。如果 OS 测试失败，应跳过所有后续测试并直接分 Bin。
2. **电流选择**：过大电流（> 5mA）可能损坏 ESD 二极管；过小电流（< 10µA）可能因噪声导致误判。通常选择 100µA ~ 500µA。
3. **电源管脚特殊处理**：对于电源/地管脚，ESD 结构可能不同（如大功率管脚可能有多个并联 ESD），需要设置不同的判定阈值。
4. **Multi-Site 考虑**：同测多颗芯片时，确保所有芯片的 OS 测试结果独立判断，避免串扰。
5. **接触电阻影响**：如果测试座（Socket）接触电阻过大，可能导致 FIMV 测量结果偏低。建议定期清洁 Socket 并做 Golden Unit 校验。

## 2. 管脚漏电测试 (Pin Leakage Test)

### 2.1 测试目的

管脚漏电测试用于验证芯片各 I/O 管脚的**输入漏电流 (Input Leakage Current)** 是否在规格范围内。漏电流过大可能表明：

- ESD 结构损坏
- I/O buffer 制造缺陷
- 管脚之间存在桥接短路
- 栅氧化层损伤

### 2.2 测试原理

根据 CMOS 电路原理，理想情况下 MOS 管的栅极漏电流极低（pA ~ nA 级）。对输入管脚施加固定电压，测量流入/流出管脚的电流，该电流即为漏电流：

- **IIH (Input High Leakage)**：管脚接 VDD 时的漏电流（电流流入管脚）
- **IIL (Input Low Leakage)**：管脚接 GND 时的漏电流（电流流出管脚）

对于双向管脚 (Bidirectional Pin)，需要分别在输入模式和输出高阻态下测试漏电。

### 2.3 测试方法

#### 输入管脚漏电测试

1. **IIL 测试**：对管脚施加 0V (或 VSS)，测量从管脚流出的电流
2. **IIH 测试**：对管脚施加 VDD，测量流入管脚的电流

#### 双向管脚漏电测试

双向管脚需先通过 JTAG/SPI 配置为输入模式或高阻态，然后执行同样的 FVMI 测试。

#### ATE 测试伪代码示例

```csharp
// 管脚漏电测试 — IIL / IIH
void PinLeakage_Test()
{
    double  VDD = 1.8;            // I/O 电压
    double  IIL_limit = 1e-6;     // 1µA (典型规格)
    double  IIH_limit = 1e-6;     // 1µA (典型规格)
    double  i_measured;

    for each (pin in InputPins)
    {
        // --- IIL 测试 ---
        PPMU_ForceVoltage(pin, 0.0);
        PPMU_MeasureCurrent(pin, out i_measured);
        if (abs(i_measured) > IIL_limit)
            TestResult_Fail(pin, "IIL_FAIL", i_measured);

        // --- IIH 测试 ---
        PPMU_ForceVoltage(pin, VDD);
        PPMU_MeasureCurrent(pin, out i_measured);
        if (abs(i_measured) > IIH_limit)
            TestResult_Fail(pin, "IIH_FAIL", i_measured);
    }

    for each (pin in BidirectionalPins)
    {
        // 先配置为输入模式
        DFT_SetPinMode(pin, INPUT_MODE);

        // 执行 IIL / IIH 测试
        PPMU_ForceVoltage(pin, 0.0);
        PPMU_MeasureCurrent(pin, out i_measured);
        // ... 判定

        PPMU_ForceVoltage(pin, VDD);
        PPMU_MeasureCurrent(pin, out i_measured);
        // ... 判定
    }
}
```

### 2.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| IIL 强制电压 | 0V (或 VSS) | 可能根据 I/O 标准略有不同 |
| IIH 强制电压 | VDD (1.2V / 1.8V / 3.3V) | 对应 I/O 电源域电压 |
| IIL/IIH 限值 | ±100nA ~ ±10µA | 视工艺和管脚类型而定 |
| 温度 | 常温 / 高温 | 高温下漏电增大，需单独测试 |
| DUT 供电 | 正常供电 | 芯片需要上电以使 I/O buffer 处于已知状态 |

### 2.5 判定标准

| 测试项 | 判定条件 | 典型限值 |
|--------|---------|---------|
| IIL (Input Low Leakage) | \|Ipin\| ≤ IIL_limit | 1µA @ 25°C |
| IIH (Input High Leakage) | \|Ipin\| ≤ IIH_limit | 1µA @ 25°C |
| 高温 IIL/IIH | \|Ipin\| ≤ IIL_HT_limit | 10µA @ 125°C |

### 2.6 注意事项

1. **漏电测试应在 OS 测试之后**：OS 测试确保管脚接触良好，避免因接触不良导致漏电误判。
2. **测试顺序敏感性**：部分管脚内部有 pull-up/pull-down 电阻，漏电测试时应考虑其影响，或先 disable 内部电阻。
3. **温度效应**：漏电流随温度升高呈指数级增大（PN 结反向饱和电流的温度系数约为 2×/10°C），高温限值需适当放宽。
4. **PPMU 量程**：漏电流通常很小（nA ~ µA 级），需要使用 PPMU 的低电流量程（如 10µA 量程）确保测量精度。
5. **Guarding 技术**：对于高精度漏电测量，应使用 Guard 环保护敏感节点，消除 PCB 表面漏电流的影响。

## 3. 管脚对地阻抗测试 (Pin-to-GND Impedance Test)

### 3.1 测试目的

管脚对地阻抗测试用于测量芯片各管脚到 GND 之间的**等效直流电阻**，主要用于：

- 验证电源管脚到 GND 的路径是否正常（无开路）
- 检测内部电路是否存在短路或异常低阻路径
- 辅助判断封装焊接质量

### 3.2 测试原理

对管脚施加一个**小电压**（确保不会使内部电路导通或触发保护机制），测量流过的电流，根据欧姆定律计算阻抗：

$$
R_{pin\_gnd} = \frac{V_{force}}{I_{measure}}
$$

由于施加的电压很小（通常 < 0.3V），不会使 ESD 二极管正向导通，因此测得的主要是管脚到 GND 的纯电阻路径。

### 3.3 测试方法

#### 测量步骤

1. 将 DUT 所有电源轨置于 GND 电位（芯片不上电）
2. 对待测管脚施加一个小电压（如 +0.1V ~ +0.3V）
3. 测量流出 PPMU 的电流
4. 计算 R = V / I
5. 对每个管脚重复上述步骤

#### ATE 测试伪代码示例

```csharp
// 管脚对地阻抗测试
void PinToGND_Impedance_Test()
{
    double  V_force = 0.2;         // 200mV 强制电压
    double  R_lo = 1.0e3;          // 下限: 1kΩ (防短路)
    double  R_hi = 10.0e6;         // 上限: 10MΩ (防开路)
    double  v_meas, i_meas, r_calc;

    for each (pin in AllPins)
    {
        PPMU_ForceVoltage(pin, V_force);
        PPMU_MeasureCurrent(pin, out i_meas);
        PPMU_MeasureVoltage(pin, out v_meas);

        r_calc = v_meas / i_meas;

        if (r_calc >= R_lo && r_calc <= R_hi)
            TestResult_Pass(pin);
        else
            TestResult_Fail(pin, "IMPEDANCE_FAIL", r_calc);
    }
}
```

### 3.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| 强制电压 (V_force) | 0.05V ~ 0.3V | 小电压避免导通 ESD 二极管 |
| 电流量程 | 取决于预期阻抗 | 低阻管脚用大电流量程，反之亦然 |
| 阻抗下限 (R_lo) | 100Ω ~ 1kΩ | 排除直短路 |
| 阻抗上限 (R_hi) | 1MΩ ~ 10MΩ | 确保连接正常 |
| DUT 供电状态 | 所有 VDD = 0V | 芯片未上电 |

### 3.5 判定标准

| 管脚类型 | 典型阻抗范围 | 说明 |
|---------|------------|------|
| 电源管脚 (VDD) | 1kΩ ~ 50kΩ | 取决于内部电源网络 |
| 地管脚 (GND) | < 10Ω | 直通到地 |
| 模拟管脚 | 10kΩ ~ 1MΩ | 高阻输入 |
| 数字 I/O | 10kΩ ~ 10MΩ | CMOS 输入为高阻 |

### 3.6 注意事项

1. **电压选择**：强制电压不能超过 ESD 二极管的导通阈值（通常约 0.5V ~ 0.7V），否则二极管导通后测得的是二极管正向压降而非真实阻抗。
2. **电容效应**：对于有大去耦电容的管脚，需等待充电稳定后再测量，否则电流瞬态会导致阻抗计算错误。
3. **电流限制**：设置 PPMU 的 compliance 电流，防止意外短路时电流过大损坏测试系统或 DUT。
4. **特殊管脚排除**：部分管脚（如测试模式管脚、高压管脚）可能有不同的阻抗特性，需要单独设定限值。

## 4. 关机电流测试 (Shutdown Current Test)

### 4.1 测试目的

关机电流（Shutdown Current）测试用于测量 PMIC 在关机模式（Shutdown / Standby / Off Mode）下的**总电流消耗**。关机电流通常要求极低（< 1µA），以确保在电池供电系统中不会因芯片本身的漏电而显著缩短电池寿命。

### 4.2 测试原理

当 PMIC 处于关机模式时，芯片内部的大部分电路被关断，仅保留必要的唤醒逻辑（如 POR 检测、按键检测等）。此时从电源输入端测量的电流即为关机电流。

**关机电流的组成**：

- 各电源轨到 GND 的静态漏电流（PN 结反向漏电、栅极漏电）
- 唤醒逻辑电路的维持电流
- 内部弱 pull-up/pull-down 电阻的偏置电流

### 4.3 测试方法

#### 关键测量技术

由于关机电流极低（nA ~ µA 级），需要使用**高精度 SMU** 或 **PPMU 的低电流量程**。关键技术包括：

1. **开尔文连接 (Kelvin / 4-Wire Sensing)**：消除线阻和接触电阻引入的测量误差
2. **Guard Ring 技术**：在 PCB 上围绕敏感节点布置保护环（Guard Ring），将有源屏蔽驱动到与敏感节点相同的电位，消除 PCB 表面漏电流
3. **多次平均采样**：降低随机噪声的影响
4. **Delta 测量**：先测背景噪声，再测信号，取差值

#### 测量步骤

1. 对芯片执行正常的 Power Down 序列，使其进入关机模式
2. 等待足够时间（通常 1ms ~ 10ms）使所有内部节点稳定
3. 使用 SMU 在电源输入端测量电流
4. 多次采样取平均值

#### ATE 测试伪代码示例

```csharp
// 关机电流测试
void Shutdown_Current_Test()
{
    double  VIN = 3.7;             // 标称输入电压
    double  I_sd_limit = 1e-6;     // 1µA 上限
    double  i_meas = 0;
    int     num_samples = 16;

    // Step 1: 正常上电
    DPS_ForceVoltage(VIN_PIN, VIN);
    DPS_ForceVoltage(VDD_IO, 1.8);

    // Step 2: 执行下电序列 (写入寄存器)
    SPI_Write(REG_SYS_CTRL, 0x00);  // 进入 Shutdown 模式
    wait(5e-3);                     // 等待内部放电完成

    // Step 3: 在 VIN 上测量电流
    DPS_SelectCurrentRange(10e-6);  // 选择 10µA 量程
    for (int i = 0; i < num_samples; i++)
    {
        double sample;
        DPS_MeasureCurrent(VIN_PIN, out sample);
        i_meas += sample;
    }
    i_meas /= num_samples;          // 取平均

    // Step 4: 判定
    if (i_meas <= I_sd_limit)
        TestResult_Pass();
    else
        TestResult_Fail("SHUTDOWN_CURRENT_FAIL", i_meas);
}
```

### 4.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| 输入电压 (VIN) | 3.0V ~ 5.5V | 根据 PMIC 工作电压范围 |
| I/O 电压 (VDD_IO) | 1.2V / 1.8V / 3.3V | 视具体芯片 |
| 温度 | 25°C / 85°C / 125°C | 高温下关机电流显著增大 |
| 关机电流限值 | < 1µA (典型) | 部分产品要求 < 0.5µA |
| 稳定等待时间 | 1ms ~ 10ms | 等待所有内部节点放电完成 |
| 采样次数 | 16 ~ 256 | 降低噪声影响 |

### 4.5 判定标准

| 温度 | 典型限值 | 说明 |
|------|---------|------|
| 25°C (常温) | ≤ 1.0µA | 标准工业级要求 |
| 85°C (高温) | ≤ 5.0µA | 高温漏电增大 |
| 125°C (极高温) | ≤ 20.0µA | 汽车级要求可能更严 |

### 4.6 注意事项

1. **PCB 表面漏电**：FT 测试中 PCB 表面的助焊剂残留、湿气吸附等可能导致表面漏电，测量值远大于芯片真实关机电流。应使用 Guard Ring 和清洗工艺解决。
2. **测试座漏电**：Socket 的绝缘材料（如 PEEK）在高温下可能产生漏电通道，需定期验证。
3. **SMU 量程切换**：从 µA 到 nA 级测量时，注意 SMU 的稳定时间，量程切换后需等待 settling time。
4. **噪声屏蔽**：关机电流测量对环境噪声极为敏感，建议使用屏蔽箱 (Shield Box) 进行测试。
5. **Golden Unit 验证**：定期使用已知良好的 Golden Unit 验证测试系统的本底噪声和漏电流。

## 5. 异常下电关机漏电测试 (Abnormal Power-Down Leakage)

### 5.1 测试目的

异常下电关机漏电测试用于模拟**电源供电异常**场景下（如某一路电源先掉电、电压跌落、半供电状态等），芯片的漏电流是否超标。该测试确保：

- 在非理想供电序列下，芯片不会出现异常的大电流路径
- 系统级电源故障时，PMIC 不会成为电池的额外负载
- 多个电源域之间不存在意外的直通路径 (Cross-Domain Leakage)

### 5.2 测试原理

在真实的便携设备中，供电序列可能因电池接触不良、连接器松动、电源管理单元故障等原因出现异常。例如：

- VDD_IO 已经掉电，但 VIN 仍然存在
- VDD_CORE 已经跌落，但 I/O 电源仍然正常
- 所有电源轨均处于中间电位（半供电状态）

在这些场景下，芯片内部不同电源域之间的 ESD 二极管可能形成意外的电流路径，导致从仍然带电的电源轨到已掉电的电源轨之间产生**反向漏电流**。

### 5.3 测试方法

#### 测试步骤

1. **单电源存在测试**：仅保留一个电源轨供电，其他电源轨浮空或接地
2. **电压偏移测试**：将一个电源轨保持正常电压，另一个电源轨缓慢拉低到 GND
3. **中间态测试**：将所有电源轨置于中间电位（如 VDD/2）
4. **反接测试**：在存在反向保护需求的管脚上施加反向电压

在每个场景下，测量带电电源上的电流损耗。

#### ATE 测试伪代码示例

```csharp
// 异常下电关机漏电测试
void Abnormal_PowerDown_Leakage_Test()
{
    // 场景 1: 仅 VIN 存在，VDD_IO = 0V
    DPS_ForceVoltage(VIN_PIN, 3.7);
    DPS_ForceVoltage(VDD_IO_PIN, 0.0);
    wait(2e-3);
    DPS_MeasureCurrent(VIN_PIN, out i_vin_only);
    if (i_vin_only > I_LEAK_LIMIT)
        TestResult_Fail("VIN_ONLY_LEAK", i_vin_only);

    // 场景 2: 仅 VDD_IO 存在，VIN = 0V
    DPS_ForceVoltage(VIN_PIN, 0.0);
    DPS_ForceVoltage(VDD_IO_PIN, 1.8);
    wait(2e-3);
    DPS_MeasureCurrent(VDD_IO_PIN, out i_vddio_only);
    if (i_vddio_only > I_LEAK_LIMIT)
        TestResult_Fail("VDDIO_ONLY_LEAK", i_vddio_only);

    // 场景 3: 半供电状态
    DPS_ForceVoltage(VIN_PIN, 1.8);     // VIN = 1.8V (半电压)
    DPS_ForceVoltage(VDD_IO_PIN, 0.9);  // VDD_IO = 0.9V (半电压)
    wait(2e-3);
    DPS_MeasureCurrent(VIN_PIN, out i_half_vin);
    DPS_MeasureCurrent(VDD_IO_PIN, out i_half_vddio);
    // ... 判定
}
```

### 5.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| VIN 电压范围 | 0V ~ 5.5V | 全范围扫描 |
| VDD_IO 电压范围 | 0V ~ 3.3V | 模拟各场景 |
| 漏电流限值 | < 10µA (典型) | 根据场景调整 |
| 测试温度 | 25°C / 85°C | 高温下风险更大 |
| 场景数量 | 3 ~ 8 种 | 取决于电源轨数量 |

### 5.5 判定标准

| 场景描述 | 判定标准 | 说明 |
|---------|---------|------|
| 仅 VIN 存在 | I(VIN) < 5µA | VIN 到掉电域不应有漏电路径 |
| 仅 VDD_IO 存在 | I(VDD_IO) < 5µA | VDD_IO 到 VIN 不应有反向漏电 |
| 半供电状态 | I_total < 10µA | 中间电位下无异常大电流 |
| 任一电源单独存在 | I < 10µA | 确保无电源域间泄漏 |

### 5.6 注意事项

1. **测试序列设计**：异常下电场景多种多样，优先选择芯片规格书中明确禁止的供电序列进行测试。
2. **ESD 二极管路径**：当某个电源域掉电而另一个仍然带电时，ESD 二极管可能正向导通，形成电流路径。检查设计是否包含反向阻断结构。
3. **时序控制**：电压切换的 slew rate 应与实际应用场景一致，避免过快的电压变化触发保护机制。
4. **复位状态**：某些芯片在检测到异常供电后会自动进入复位状态，需确认测试时芯片处于正确的状态。

## 6. DFT 测试 (Design for Test)

### 6.1 测试目的

DFT (Design for Test) 测试用于验证芯片内部集成的**可测试性设计电路**是否正常工作。DFT 电路的设计目的是：

- 提供对芯片内部节点的可控性和可观测性
- 支持扫描链测试 (Scan Chain Test) 发现制造缺陷
- 实现旁路模式 (Bypass Mode) 绕过有缺陷的模块
- 配置测试多路选择器 (Test Mux) 将内部信号路由到管脚

### 6.2 测试原理

PMIC 中集成的 DFT 结构通常包括：

#### 6.2.1 扫描链 (Scan Chain)

将芯片内的普通触发器连接成移位寄存器链。在测试模式下：

- **Shift 模式**：通过扫描输入 (Scan In) 移入测试向量，通过扫描输出 (Scan Out) 移出捕获结果
- **Capture 模式**：施加时钟脉冲，捕获组合逻辑的输出状态

#### 6.2.2 测试多路选择器 (Test Mux / Test Bus)

将内部模拟信号（如 VREF、BGAP、IREF、比较器输出等）通过模拟多路选择器路由到测试管脚（如 TEST_PIN、MON_OUT），便于 ATE 直接测量内部关键节点电压。

#### 6.2.3 旁路模式 (Bypass Mode)

在某个模块（如 LDO、Buck）失效时，可以通过 DFT 寄存器将该模块置于旁路模式，将输入直接连接到输出，维持系统的基本功能。

### 6.3 测试方法

#### 扫描链测试

```csharp
// DFT 扫描链测试
void DFT_ScanChain_Test()
{
    // Step 1: 进入 DFT 模式
    SPI_Write(REG_DFT_CTRL, 0x01);    // 使能 DFT 模式
    DFT_SetPinMode(TEST_EN, HIGH);     // 拉高测试使能

    // Step 2: 移位模式 — 移入测试向量
    uint64_t test_pattern = 0xA5A5A5A5A5A5A5A5;
    uint64_t scan_out;

    // 移入向量
    for (int i = 0; i < SCAN_CHAIN_LENGTH; i++)
    {
        digital_write(SCAN_CLK, LOW);
        digital_write(SCAN_IN, (test_pattern >> i) & 0x01);
        digital_write(SCAN_CLK, HIGH);
    }

    // Step 3: 捕获模式
    digital_write(SCAN_CLK, LOW);
    wait(1e-6);
    digital_write(SCAN_CLK, HIGH);

    // Step 4: 移出结果
    scan_out = 0;
    for (int i = 0; i < SCAN_CHAIN_LENGTH; i++)
    {
        digital_write(SCAN_CLK, LOW);
        scan_out |= (digital_read(SCAN_OUT) << i);
        digital_write(SCAN_CLK, HIGH);
    }

    // Step 5: 比较期望值
    if (scan_out != EXPECTED_SCAN_OUT)
        TestResult_Fail("SCAN_CHAIN_FAIL", scan_out);
    else
        TestResult_Pass();
}
```

#### Test Mux 测量

```csharp
// DFT Test Mux — 内部电压测量
void DFT_TestMux_Measure()
{
    // Step 1: 配置 Test Mux 选择 VREF
    SPI_Write(REG_TEST_MUX_SEL, 0x01);  // MUX 选择通道 1 = VREF

    // Step 2: 在 TEST_PIN 上测量输出电压
    double v_vref;
    PPMU_MeasureVoltage(TEST_PIN, out v_vref);

    // Step 3: 判定 VREF 是否在范围内
    if (v_vref >= 1.18 && v_vref <= 1.22)
        TestResult_Pass();
    else
        TestResult_Fail("VREF_VIA_DFT_FAIL", v_vref);
}
```

### 6.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| DFT 使能电压 (TEST_EN) | VDD_IO 电平 | 高电平使能 DFT 模式 |
| 扫描时钟频率 | 1MHz ~ 20MHz | 取决于 DFT 设计 |
| 测试向量长度 | 100 ~ 10000 bits | 取决于扫描链长度 |
| 测试覆盖率 | > 95% (目标) | 工业级要求 |
| Test Mux 通道数 | 8 ~ 64 | 取决于芯片复杂度 |

### 6.5 判定标准

| 测试项 | 判定条件 |
|--------|---------|
| 扫描链移位 | 移入向量与移出向量一致 |
| 扫描链捕获 | 捕获结果与预期值一致 |
| Test Mux 电压 | 测量值与预期值的偏差 < ±5% |
| Bypass 模式 | 旁路导通阻抗在规格范围内 |

### 6.6 注意事项

1. **DFT 模式隔离**：DFT 测试时，芯片处于特殊工作模式，应确保 DFT 模式下的功耗、电流不会超过系统限制。
2. **测试模式管脚复用**：很多 DFT 管脚与功能管脚复用，测试完成后必须恢复为功能模式。
3. **安全考虑**：某些 DFT 模式可能允许操作修调寄存器（Trim Register），需要使用写保护机制防止误修改。
4. **ATE 时序校准**：扫描链测试对时序要求严格，需要先做 ATE 通道的时序校准 (Timing Calibration)。
5. **ATPG 向量**：扫描链测试向量通常由 ATPG (Automatic Test Pattern Generation) 工具生成，需要验证向量在 ATE 上的正确运行。

## 7. 系统开机电压测试 (System Power-On Voltage / UVLO)

### 7.1 测试目的

系统开机电压测试用于测量 PMIC 的**上电阈值 (V_POR_Rising)** 和**下电阈值 (V_POR_Falling)**，即 UVLO (Under-Voltage Lockout) 的阈值和迟滞特性。该测试确保：

- 芯片在输入电压上升到足够高时才启动（防止低电压下误启动）
- 芯片在输入电压下降到一定程度时可靠关断（防止低电压下不稳定工作）
- UVLO 迟滞 (Hysteresis) 防止在阈值附近发生震荡 (Chattering)

### 7.2 测试原理

PMIC 内部通常集成有一个电压检测比较器（UVLO Comparator），持续监测输入电压 (VIN)：

- **V_POR_Rising**：当 VIN 从 0V 上升，超过该阈值时，芯片退出复位状态，开始上电初始化
- **V_POR_Falling**：当 VIN 从正常电压下降，低于该阈值时，芯片进入复位/关断状态
- **迟滞 (Hysteresis)**：V_POR_Rising - V_POR_Falling，用于防止阈值附近的震荡

### 7.3 测试方法

#### 上升阈值测量

1. DUT 初始为 VIN = 0V，其他电源轨正常
2. VIN 从 0V 开始以固定斜率（如 100mV/s）上升
3. 监测芯片是否启动（通过监测输出管脚电压、I²C 通信能力或 POR 标志寄存器）
4. 记录芯片启动时的 VIN 电压值

#### 下降阈值测量

1. DUT 正常供电（VIN 高于 V_POR_Rising）
2. VIN 以固定斜率下降
3. 监测芯片是否关断（输出管脚电压归零、I²C 通信中断或 POR 标志置位）
4. 记录芯片关断时的 VIN 电压值

#### ATE 测试伪代码示例

```csharp
// 系统开机电压测试 (UVLO)
void UVLO_Threshold_Test()
{
    double VIN_start = 0.0;
    double VIN_step  = 0.01;       // 10mV step
    double v_rising = 0, v_falling = 0;

    // --- 上升阈值 ---
    DPS_ForceVoltage(VIN_PIN, 0.0);
    for (double v = 0; v <= 5.0; v += VIN_step)
    {
        DPS_ForceVoltage(VIN_PIN, v);
        wait(100e-6);              // 等待稳定

        // 检查 POR 状态寄存器
        uint8_t por_status = SPI_Read(REG_POR_STATUS);
        if (por_status & POR_DONE_MASK)
        {
            v_rising = v;
            break;
        }
    }

    // --- 下降阈值 ---
    for (double v = 5.0; v >= 0; v -= VIN_step)
    {
        DPS_ForceVoltage(VIN_PIN, v);
        wait(100e-6);

        uint8_t por_status = SPI_Read(REG_POR_STATUS);
        if (!(por_status & POR_DONE_MASK))
        {
            v_falling = v;
            break;
        }
    }

    // 判定
    double hysteresis = v_rising - v_falling;
    if (v_rising >= V_POR_RISING_MIN && v_rising <= V_POR_RISING_MAX &&
        hysteresis >= HYST_MIN && hysteresis <= HYST_MAX)
        TestResult_Pass();
    else
        TestResult_Fail("UVLO_FAIL", v_rising, v_falling, hysteresis);
}
```

### 7.4 测试条件

| 参数 | 典型规格 | 说明 |
|------|---------|------|
| V_POR_Rising (上升阈值) | 2.5V ~ 3.2V | 视 PMIC 设计而定 |
| V_POR_Falling (下降阈值) | 2.0V ~ 2.8V | 通常比上升阈值低 200mV ~ 500mV |
| 迟滞 (Hysteresis) | 200mV ~ 500mV | 防震荡余量 |
| 电压扫描步进 | 10mV ~ 50mV | 精度与测试时间的折中 |
| 温度 | 25°C / -40°C / 125°C | 全温度范围验证 |
| 扫描速度 | 50mV/s ~ 500mV/s | 不能太快，防止电容效应导致误差 |

### 7.5 判定标准

| 参数 | 最小值 | 典型值 | 最大值 | 单位 |
|------|-------|--------|-------|------|
| V_POR_Rising | 2.3 | 2.8 | 3.3 | V |
| V_POR_Falling | 1.8 | 2.3 | 2.8 | V |
| 迟滞 | 200 | 500 | 800 | mV |

### 7.6 注意事项

1. **扫描速度**：VIN 扫描速度不能太快，否则片上电容（去耦电容）会导致测量到的阈值偏移。建议使用准静态扫描（Quasi-Static Sweep）。
2. **去耦电容**：DUT Board 上的去耦电容会影响扫描测量结果。小电容（< 1µF）可以保留，大电容应去除或通过 Kelvin 连接补偿。
3. **迟滞验证**：务必同时测量上升和下降两个方向，仅测单方向无法验证迟滞。
4. **温度系数**：UVLO 阈值随温度变化，高温下阈值可能降低。需要在全温度范围内验证。
5. **噪声抑制**：阈值附近的比较器可能因噪声产生误触发。在测量时使用平均滤波或迟滞模式下的 Shmoo 扫描。

## 8. 低功耗电流测试 (Low Power Current)

### 8.1 测试目的

低功耗电流测试用于测量 PMIC 在**各种低功耗工作模式**下的电流消耗。现代 PMIC 通常支持多种电源状态（Power State），在不同负载/使用场景下切换以优化系统功耗。本测试覆盖以下模式：

- **IDLE 模式**：芯片处于工作状态（Active），但无输出负载，维持基本功能
- **SUSPEND 模式**：部分模块关断，仅保持关键功能（如寄存器状态、RTC）
- **AO (Always-On) 模式**：始终保持供电的关键电路（如唤醒检测、实时时钟）

### 8.2 测试原理

PMIC 通过内部的电源管理状态机 (Power Management State Machine) 控制各模块的供电：

- **IDLE 模式**：系统时钟正常工作，所有稳压器使能（Enable）但无负载。电流主要为稳压器的静态电流和控制逻辑的功耗
- **SUSPEND 模式**：关闭高频时钟和大部分稳压器，仅保留低频时钟（如 32K RTC）和必要的唤醒逻辑。电流通常在 µA 级
- **AO 模式**：始终保持导电的域（Always-On Domain），包括 POR 检测、唤醒检测（如按键检测、VBUS 检测）、RTC 振荡器。电流通常在 nA ~ µA 级

### 8.3 测试方法

三种模式的测试方法类似，差异在于芯片的工作状态配置不同。每个模式下使用 SMU 在供电电源上测量总电流。

#### ATE 测试伪代码示例

```csharp
// 低功耗电流测试 — 三种模式
void LowPower_Current_Test()
{
    double i_idle, i_suspend, i_ao;

    // === IDLE 模式 ===
    // 配置: 所有稳压器使能, 空载
    SPI_Write(REG_SYS_MODE, 0x01);      // IDLE 模式
    SPI_Write(REG_LDO1_CTRL, 0x01);     // LDO1 使能
    SPI_Write(REG_BUCK1_CTRL, 0x01);    // BUCK1 使能
    wait(2e-3);                          // 等待稳定

    DPS_SelectCurrentRange(10e-3);       // 10mA 量程
    DPS_MeasureCurrent(VIN_PIN, out i_idle);

    // === SUSPEND 模式 ===
    SPI_Write(REG_SYS_MODE, 0x02);      // SUSPEND 模式
    SPI_Write(REG_LDO1_CTRL, 0x00);     // LDO1 关闭
    SPI_Write(REG_BUCK1_CTRL, 0x00);    // BUCK1 关闭
    wait(5e-3);

    DPS_SelectCurrentRange(100e-6);      // 100µA 量程
    DPS_MeasureCurrent(VIN_PIN, out i_suspend);

    // === AO 模式 ===
    SPI_Write(REG_SYS_MODE, 0x03);      // AO 模式 (Shutdown, 仅保留 AO domain)
    wait(5e-3);

    DPS_SelectCurrentRange(10e-6);       // 10µA 量程
    DPS_MeasureCurrent(VIN_PIN, out i_ao);

    // 判定
    if (i_idle <= I_IDLE_MAX &&
        i_suspend <= I_SUSPEND_MAX &&
        i_ao <= I_AO_MAX)
        TestResult_Pass();
    else
        TestResult_Fail("LOW_POWER_CURRENT_FAIL", i_idle, i_suspend, i_ao);
}
```

### 8.4 测试条件

| 参数 | IDLE 模式 | SUSPEND 模式 | AO 模式 |
|------|----------|-------------|---------|
| 输入电压 (VIN) | 3.7V | 3.7V | 3.7V |
| I/O 电压 | 1.8V | 1.8V | 1.8V |
| 典型电流 | 100µA ~ 1mA | 1µA ~ 20µA | < 1µA |
| 测试量程 | 10mA | 100µA | 10µA |
| 稳定时间 | 2ms | 5ms | 10ms |
| 温度 | 25°C / 85°C | 25°C / 85°C | 25°C / 85°C |

### 8.5 判定标准

| 模式 | 25°C (常温) | 85°C (高温) | 说明 |
|------|------------|------------|------|
| IDLE | ≤ 500µA | ≤ 1mA | 空载工作电流 |
| SUSPEND | ≤ 10µA | ≤ 50µA | 保持寄存器和唤醒逻辑 |
| AO | ≤ 1µA | ≤ 5µA | 仅保留关键唤醒电路 |

### 8.6 注意事项

1. **模式切换顺序**：严格按照芯片规格书要求的序列切换电源状态，跳过某些步骤可能导致芯片进入未知状态。
2. **电流量程切换**：不同模式的电流差异可达 1000 倍，SMU 量程切换时需留出足够的时间等待量程稳定。
3. **外部负载**：低功耗测试时，所有稳压器的输出端不应有外部负载。如果 DUT Board 上有固定负载电阻，需通过计算扣除其影响。
4. **唤醒源**：AO 模式下，需确认所有不必要的唤醒源（如 VBUS 检测、按键检测）已被 disable，否则电流会偏高。
5. **去耦电容漏电**：板上大电容的漏电（尤其是电解电容）可能远大于芯片自身的 AO 电流，应使用低漏电陶瓷电容。

## 9. 下拉电阻测试 (Pull-Down Resistor Test)

### 9.1 测试目的

下拉电阻测试用于验证芯片内部集成的**下拉电阻 (Pull-Down Resistor)** 的阻值是否在设计规格范围内。内部下拉电阻用于：

- 在管脚悬空时提供确定的逻辑电平（默认低电平）
- 防止浮空输入导致的反相器振荡和额外功耗
- 在芯片未使能时确保输出管脚处于安全状态

### 9.2 测试原理

在 CMOS 电路中，内部下拉电阻通常由多晶硅电阻 (Poly Resistor) 或 MOS 管构成的等效电阻实现。测试方法是对管脚施加一个已知电压，测量流过的电流，根据欧姆定律计算电阻值：

$$
R_{pd} = \frac{V_{force}}{I_{measure}}
$$

**关键点**：施加的电压必须足够低，确保不会使 ESD 二极管导通，同时又要足够高以获得可测量的电流。

### 9.3 测试方法

#### 测量步骤

1. 确保芯片处于正常工作状态，内部下拉电阻已使能
2. 对待测管脚施加一个电压（通常选择 VDD_IO × 0.5 或 VDD_IO × 0.7）
3. 测量流入管脚的电流
4. 记录电压和电流值，计算电阻

#### ATE 测试伪代码示例

```csharp
// 下拉电阻测试
void PullDown_Resistor_Test()
{
    double  V_force = 1.0;         // 强制 1.0V
    double  R_pd_min = 10e3;       // 10kΩ 下限
    double  R_pd_max = 100e3;      // 100kΩ 上限
    double  v_meas, i_meas, r_calc;

    for each (pin in PullDownPins)
    {
        // 确保该管脚的下拉电阻已使能
        // (通常有配置寄存器控制)
        SPI_Write(REG_PULLDWN_CTRL, PinToBit(pin));

        PPMU_ForceVoltage(pin, V_force);
        PPMU_MeasureCurrent(pin, out i_meas);
        PPMU_MeasureVoltage(pin, out v_meas);

        r_calc = v_meas / i_meas;

        if (r_calc >= R_pd_min && r_calc <= R_pd_max)
            TestResult_Pass(pin);
        else
            TestResult_Fail(pin, "PD_RES_FAIL", r_calc);
    }
}
```

### 9.4 测试条件

| 参数 | 典型规格 | 说明 |
|------|---------|------|
| 强制电压 (V_force) | VDD_IO × 0.5 ~ 0.7 | 确保不导通 ESD 二极管 |
| 电阻规格 (R_pd) | 10kΩ ~ 100kΩ | 常见内部下拉电阻范围 |
| 测试精度 | ±10% ~ ±20% | 取决于电阻类型 |
| 温度 | 25°C / 125°C | 多晶硅电阻有温度系数 |

### 9.5 判定标准

| 标称值 | 最小 | 最大 | 单位 |
|--------|------|------|------|
| 10k | 7 | 13 | kΩ |
| 20k | 14 | 28 | kΩ |
| 50k | 35 | 75 | kΩ |
| 100k | 70 | 150 | kΩ |

### 9.6 注意事项

1. **ESD 保护影响**：强制电压不能使 ESD 二极管导通。对于有到 VDD 的 ESD 二极管的管脚，强制电压应 < VDD - 0.5V。
2. **温度系数**：多晶硅电阻具有正温度系数 (PTC)，温度升高时阻值增大。高温测试的限值应适当调整。
3. **同时测试多个管脚**：不建议同时测量多个使能了下拉电阻的管脚，因为总电流是各管脚电流之和，无法单独计算。
4. **数字逻辑冲突**：如果管脚同时被外部驱动或内部有输出 buffer 使能，会导致测量冲突。测试前需确保输出 buffer 为高阻态。
5. **寄存器配置**：下拉电阻的使能/禁用在测试前需正确配置，测试完成后应恢复默认状态。

## 10. 系统过压保护测试 (System OVP)

### 10.1 测试目的

系统过压保护测试用于验证 PMIC 的**过压保护 (Over-Voltage Protection, OVP)** 阈值是否在规格范围内。当输入电压超过安全上限时，OVP 电路应：

- 关断功率管以防止输出过压损坏负载
- 或钳位输入电压到安全电平
- 并通过中断或状态寄存器上报过压事件

### 10.2 测试原理

PMIC 内部集成 OVP 比较器，持续监测输入电压 (VIN)。当 VIN 超过 OVP 阈值（V_OVP_TH）时，比较器翻转并触发保护动作：

- **保护动作**：关断功率级（Power Stage），停止能量传输
- **恢复方式**：自动恢复（Autorecovery）或锁存（Latch-off），取决于设计
- **响应时间**：从过压发生到保护动作的时间，通常在 µs 级

### 10.3 测试方法

#### 方法一：DC 扫描法（静态 OVP 阈值）

1. DUT 正常工作（使能输出稳压器）
2. VIN 从标称值缓慢上升，直到 OVP 触发
3. 通过监测输出管脚电压下降或读取 OVP 状态寄存器判断触发点
4. 记录触发时的 VIN 电压

#### 方法二：瞬态 OVP 测试

1. DUT 正常工作
2. 使用 AWG 在 VIN 上叠加一个过压脉冲
3. 监测 OVP 触发时间和恢复时间

#### ATE 测试伪代码示例

```csharp
// 系统 OVP 测试 — DC 扫描法
void System_OVP_Test()
{
    double  VIN_nom = 3.7;         // 标称输入电压
    double  VIN_step = 0.05;       // 50mV 步进
    double  v_ovp_th = 0;

    // Step 1: 正常上电并使能输出
    DPS_ForceVoltage(VIN_PIN, VIN_nom);
    SPI_Write(REG_BUCK_CTRL, 0x01);  // 使能 Buck
    wait(2e-3);

    // Step 2: 缓慢升高 VIN 直到 OVP 触发
    for (double v = VIN_nom; v <= 7.0; v += VIN_step)
    {
        DPS_ForceVoltage(VIN_PIN, v);
        wait(500e-6);

        // 检查 OVP 状态寄存器
        uint8_t ovp_flag = SPI_Read(REG_FAULT_STATUS);
        if (ovp_flag & OVP_FLAG_MASK)
        {
            v_ovp_th = v;
            break;
        }

        // 或者监测输出电压是否下降
        double vout;
        PPMU_MeasureVoltage(VOUT_PIN, out vout);
        if (vout < VOUT_NOM * 0.9)   // 输出下降 10% 视为触发
        {
            v_ovp_th = v;
            break;
        }
    }

    // Step 3: 判定
    if (v_ovp_th >= V_OVP_MIN && v_ovp_th <= V_OVP_MAX)
        TestResult_Pass();
    else
        TestResult_Fail("OVP_FAIL", v_ovp_th);
}
```

### 10.4 测试条件

| 参数 | 典型规格 | 说明 |
|------|---------|------|
| OVP 阈值 (V_OVP_TH) | 5.5V ~ 6.5V | 视 PMIC 额定电压而定 |
| 标称输入 (VIN) | 3.7V ~ 5.0V | 正常工作电压 |
| 电压扫描范围 | VIN_nom ~ 7.0V | 上限需高于 OVP 阈值 |
| 保护响应时间 | < 10µs | 从过压到保护动作 |
| 温度 | 25°C / 125°C | OVP 阈值有温度系数 |

### 10.5 判定标准

| 参数 | 最小值 | 典型值 | 最大值 | 单位 |
|------|-------|--------|-------|------|
| OVP 上升阈值 | 5.2 | 5.8 | 6.4 | V |
| OVP 恢复阈值（迟滞） | 4.8 | 5.3 | 5.8 | V |
| 迟滞量 | 200 | 500 | 800 | mV |

### 10.6 注意事项

1. **扫描方向**：始终从低到高扫描，避免从高到低扫描时芯片已在 OVP 锁存状态。
2. **自恢复 vs 锁存**：区分 OVP 后的恢复行为。锁存型 OVP 需要 VIN 降到 UVLO 以下或 POR 才能恢复；自恢复型在 VIN 回落到迟滞阈值以下后自动恢复。
3. **功率限制**：OVP 测试时 VIN 较高，注意 DUT 的功耗限制，避免因长时间过压导致热损坏。
4. **输出管脚监测**：如果使用输出管脚电压监测 OVP 触发，需确保输出端有足够的负载以在 OVP 触发后观察到电压下降。
5. **状态寄存器读取**：最优方法是通过 SPI/I²C 读取 OVP 寄存器状态，这比外部电压监测更可靠。

## 11. 系统欠压测试 (System UVLO / Brownout)

### 11.1 测试目的

系统欠压测试用于验证 PMIC 的**欠压锁定 (Under-Voltage Lockout, UVLO)** 和**棕出检测 (Brownout Detection)** 功能：

- 确保 VIN 下降到 UVLO 阈值以下时芯片可靠关断
- 确保 VIN 回升到 UVLO 阈值以上时芯片正常重启
- 验证电压跌落 (Brownout) 事件的检测与上报

### 11.2 测试原理

UVLO 电路监测 VIN 电压，当 VIN 低于 UVLO 阈值时：

- 芯片进入复位状态（POR 有效）
- 所有输出稳压器关断
- 内部状态丢失（寄存器复位为默认值）
- 当 VIN 回升到 UVLO 上升阈值以上时，芯片重新初始化

**Brownout 与 UVLO 的区别**：

- **UVLO**：电压完全低于阈值，芯片进入深度关断
- **Brownout**：电压短暂跌落（ms 级），芯片可能维持部分功能，但需要检测并上报

### 11.3 测试方法

#### UVLO 阈值测试（与系统开机电压测试类似，但侧重下电阈值）

1. DUT 正常上电
2. VIN 以固定斜率下降，监测芯片关断点（V_POR_Falling）
3. VIN 回升，监测芯片重启点（V_POR_Rising）

#### Brownout 检测测试

1. DUT 正常工作
2. 在 VIN 上施加一个短暂的电压跌落脉冲（幅度和宽度可编程）
3. 检查芯片是否检测到 Brownout 事件（通过状态寄存器）
4. 检查 Brownout 期间/之后的芯片行为

#### ATE 测试伪代码示例

```csharp
// UVLO / Brownout 测试
void UVLO_Brownout_Test()
{
    // === Test 1: UVLO 下降阈值 ===
    DPS_ForceVoltage(VIN_PIN, 5.0);
    SPI_Write(REG_BUCK_CTRL, 0x01);     // 使能输出
    wait(2e-3);

    double v_uvlo_falling = 0;
    for (double v = 5.0; v >= 0; v -= 0.02)   // 20mV step
    {
        DPS_ForceVoltage(VIN_PIN, v);
        wait(200e-6);

        // 监测输出
        double vout;
        PPMU_MeasureVoltage(VOUT_PIN, out vout);
        if (vout < 0.1)     // 输出关断
        {
            v_uvlo_falling = v;
            break;
        }
    }

    // === Test 2: Brownout 脉冲测试 ===
    DPS_ForceVoltage(VIN_PIN, 5.0);
    wait(5e-3);

    // 模拟 VIN 跌落: 5.0V -> 3.0V -> 5.0V, 宽度 1ms
    AWG_GeneratePulse(VIN_PIN, 5.0, 3.0, 1e-3, 100e-6);
    wait(2e-3);

    // 检查 Brownout 状态
    uint8_t fault_reg = SPI_Read(REG_FAULT_STATUS);
    if (fault_reg & BROWNOUT_FLAG_MASK)
        TestResult_Pass("BROWNOUT_DETECTED");
    else
        TestResult_Fail("BROWNOUT_NOT_DETECTED");

    // 判定 UVLO 阈值
    if (v_uvlo_falling >= V_UVLO_FALL_MIN && v_uvlo_falling <= V_UVLO_FALL_MAX)
        TestResult_Pass();
    else
        TestResult_Fail("UVLO_FALL_FAIL", v_uvlo_falling);
}
```

### 11.4 测试条件

| 参数 | 典型规格 | 说明 |
|------|---------|------|
| UVLO 下降阈值 | 2.0V ~ 2.5V | 电压跌落时触发 UVLO |
| UVLO 上升阈值 | 2.3V ~ 2.8V | 电压恢复时退出 UVLO |
| Brownout 检测阈值 | 2.5V ~ 3.0V | 低于此值触发 Brownout 警告 |
| Brownout 脉冲宽度 | 100µs ~ 10ms | 模拟实际电源跌落场景 |
| 测试温度 | 25°C / 125°C | — |

### 11.5 判定标准

| 参数 | 最小值 | 典型值 | 最大值 | 单位 |
|------|-------|--------|-------|------|
| UVLO 上升阈值 | 2.3 | 2.6 | 2.9 | V |
| UVLO 下降阈值 | 1.8 | 2.2 | 2.6 | V |
| Brownout 检测阈值 | 2.5 | 2.8 | 3.1 | V |

### 11.6 注意事项

1. **阈值重叠**：UVLO 阈值与系统开机电压（V_POR）阈值通常相同或接近，注意测试时不要混淆。
2. **Brownout 脉冲参数**：脉冲幅度和宽度需要精确控制，过浅或过短的脉冲可能无法触发 Brownout 检测。
3. **恢复行为**：测试后需要验证芯片是否能正确恢复所有功能，包括寄存器值是否恢复为默认值。
4. **滤波时间**：UVLO 比较器通常有去抖滤波（Debounce Filter），防止噪声引起的误触发。测试时需要考虑滤波时间的影响。
5. **负载影响**：大的输出电容可能在 VIN 跌落时维持输出电压一段时间，导致 UVLO 检测延迟。需在适当负载条件下测试。

## 12. FAULT_N 上报/响应测试 (FAULT_N Report/Response)

### 12.1 测试目的

FAULT_N 上报/响应测试用于验证 PMIC 的**故障上报管脚 (FAULT_N / nINT / IRQ)** 功能是否正常。FAULT_N 通常是一个**开漏 (Open-Drain) 输出**管脚，在检测到故障事件时被拉低，向系统主控 (SoC / AP) 上报异常。本测试验证：

- FAULT_N 管脚在正常状态下的高阻态（靠外部上拉电阻维持高电平）
- FAULT_N 管脚在故障事件下的下拉能力
- 故障消除后 FAULT_N 的恢复行为（自动恢复或需清除寄存器）
- 故障上报的时序特性

### 12.2 测试原理

FAULT_N 的典型电路结构如下：

```
                  VDD_PULL
                     |
                    R_pull (外部上拉, 如 10kΩ)
                     |
    PMIC ──┬── FAULT_N ─────── SoC GPIO
           │
          ┌─┘
          │  NMOS (开漏驱动)
          └─┘
             │
            GND
```

- **正常状态**：NMOS 关断，FAULT_N 被外部上拉电阻拉到 VDD_PULL（高电平）
- **故障状态**：NMOS 导通，FAULT_N 被拉到 GND（低电平）
- 支持多个故障源通过线与 (Wire-AND) 连接

可触发的故障类型包括：

| 故障类型 | 触发条件 |
|---------|---------|
| OVP (过压) | VIN 超过 OVP 阈值 |
| UVLO (欠压) | VIN 低于 UVLO 阈值 |
| OCP (过流) | 输出电流超过 OCP 阈值 |
| SCP (短路) | 输出短路到 GND |
| OTP (过温) | 芯片温度超过 OTP 阈值 |
| Power Good Fault | 输出未达到 PG 阈值 |

### 12.3 测试方法

#### 基本功能测试

1. **正常状态验证**：确认 FAULT_N 为高电平（上拉后的电压）
2. **触发故障**：通过施加过压/过流等条件触发故障事件
3. **上报验证**：确认 FAULT_N 被拉低到 VOL（低电平电压）
4. **恢复验证**：清除故障源后，确认 FAULT_N 恢复为高电平

#### 时序测试

测量从故障事件发生到 FAULT_N 被拉低的延迟时间（t_FAULT_PROP）。

#### 下拉能力测试

在 FAULT_N 上接一个下拉测试电阻（模拟上拉负载），测量 FAULT_N 被拉低时的电压，验证下拉驱动能力。

#### ATE 测试伪代码示例

```csharp
// FAULT_N 功能测试
void FAULT_N_Test()
{
    double  V_pull = 1.8;           // 上拉电压
    double  V_OL_max = 0.4;         // 低电平电压上限 (400mV)
    double  t_fault_prop_max = 10e-6; // 最大传播延迟 10µs

    // Step 1: 正常状态 — FAULT_N 应为高电平
    double v_fn;
    PPMU_ForceVoltage(FAULT_N_PIN, V_pull);
    PPMU_MeasureVoltage(FAULT_N_PIN, out v_fn);
    if (v_fn < V_pull * 0.8)
        TestResult_Fail("FAULT_N_IDLE_LOW");

    // Step 2: 触发 OVP 故障
    DPS_ForceVoltage(VIN_PIN, 6.5);   // 超过 OVP 阈值
    wait(1e-3);

    // 测量 FAULT_N 电压
    PPMU_MeasureVoltage(FAULT_N_PIN, out v_fn);
    if (v_fn > V_OL_max)
        TestResult_Fail("FAULT_N_NOT_PULLED_LOW");

    // Step 3: 读取故障寄存器确认
    uint8_t fault_reg = SPI_Read(REG_FAULT_STATUS);
    if (!(fault_reg & OVP_FAULT_MASK))
        TestResult_Fail("OVP_FAULT_NOT_REPORTED");

    // Step 4: 清除故障并恢复
    SPI_Write(REG_FAULT_CLEAR, 0xFF);  // 清除所有故障标志
    DPS_ForceVoltage(VIN_PIN, 3.7);    // 恢复 VIN

    wait(2e-3);
    PPMU_MeasureVoltage(FAULT_N_PIN, out v_fn);
    if (v_fn < V_pull * 0.8)
        TestResult_Fail("FAULT_N_NOT_RECOVERED");

    TestResult_Pass();
}
```

### 12.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| 外部上拉电阻 | 4.7kΩ ~ 100kΩ | 视实际应用设计 |
| 上拉电压 (VDD_PULL) | 1.8V / 3.3V | 与系统 I/O 电压匹配 |
| 低电平电压 (V_OL) | < 0.4V | 标准 LVCMOS 阈值 |
| 传播延迟 | < 10µs | 从故障发生到 FAULT_N 拉低 |
| 最小脉冲宽度 | > 1µs | FAULT_N 应保持低电平 |

### 12.5 判定标准

| 测试项 | 判定条件 |
|--------|---------|
| 正常状态下 FAULT_N 电平 | ≥ VDD_PULL × 0.8 |
| 故障状态下 FAULT_N 电平 | ≤ 0.4V |
| 故障寄存器状态 | 对应故障位有效 |
| 故障清除后 FAULT_N 恢复 | ≥ VDD_PULL × 0.8 |
| 传播延迟 | ≤ 10µs |

### 12.6 注意事项

1. **开漏特性验证**：FAULT_N 是开漏输出，测试时不能强制电压驱动，只能通过上拉电阻测量电平。
2. **多故障源并发**：如果有多个故障同时发生，FAULT_N 保持低电平直到所有故障被清除。测试时需要验证多故障场景。
3. **上拉电阻匹配**：测试板的上拉电阻应与应用电路一致，过大的上拉电阻会使低电平电压升高。
4. **软件清除 vs 自动清除**：区分 FAULT_N 的两种恢复机制：
   - **锁存模式**：需通过 SPI/I²C 写寄存器清除
   - **自动清除**：故障源消失后自动恢复
5. **启动时的 FAULT_N**：芯片上电过程中，FAULT_N 可能短暂拉低（表示芯片正在初始化）。测试时需要避开这段不稳定时间。

## 13. 硬线开关控制测试 (Hardware Switch Control)

### 13.1 测试目的

硬线开关控制测试用于验证 PMIC 的**硬件控制管脚**（如 EN、ON/OFF、SLEEP、HW_EN 等）功能是否正常。这些管脚通过**专用硬件引脚**直接控制芯片的开关行为，不依赖 I²C/SPI 总线。本测试确保：

- EN/ON 管脚能正确使能/关断 PMIC
- 关断模式下电流符合规格
- 使能延迟（从 EN 拉高到输出稳定）在规格范围内

### 13.2 测试原理

硬线控制管脚是 PMIC 最基本的控制接口，直接连接到芯片的电源管理状态机：

- **EN = High / ON**：芯片上电，启动内部电源管理序列，各稳压器按预设顺序输出
- **EN = Low / OFF**：芯片下电，各稳压器按顺序关断，进入最低功耗状态

典型的 HW 开关控制时序：

```
EN  ───────┐                ┌──────────
           │                │
           │                │
           └────────────────┘
              ↑              ↑
            t_dly_ON      t_dly_OFF
              │              │
VOUT  ────────┴──────┐   ┌──┴─────────
                     │   │
                     └───┘
```

### 13.3 测试方法

#### 功能测试

1. 保持 EN 为低电平，确认芯片处于关断状态（VOUT = 0V）
2. 将 EN 拉高，监测 VOUT 是否按预期上电
3. 将 EN 拉低，监测 VOUT 是否按预期下电

#### 时序测试

1. 测量 t_dly_ON：从 EN 上升沿（50% 阈值）到 VOUT 上升沿（10% 阈值）的延迟
2. 测量 t_dly_OFF：从 EN 下降沿（50% 阈值）到 VOUT 下降沿（90% 阈值）的延迟
3. 测量 VOUT 上升时间（10% ~ 90%）

#### ATE 测试伪代码示例

```csharp
// 硬线开关控制测试
void HW_Switch_Control_Test()
{
    // Step 1: EN = Low → 确认关断
    Digital_Drive(EN_PIN, LOW);
    wait(1e-3);

    double vout;
    PPMU_MeasureVoltage(VOUT_PIN, out vout);
    if (vout > 0.1)
        TestResult_Fail("VOUT_NOT_OFF");

    // Step 2: EN = High → 测量上电延迟
    Timer_Start();
    Digital_Drive(EN_PIN, HIGH);

    // 等待 VOUT 上升
    wait_for_voltage(VOUT_PIN, VOUT_NOM * 0.9, 10e-3);
    double t_on = Timer_Elapsed();

    if (t_on > T_ON_MAX)
        TestResult_Fail("TURN_ON_DELAY_FAIL", t_on);

    // Step 3: EN = Low → 测量下电延迟
    Timer_Start();
    Digital_Drive(EN_PIN, LOW);

    wait_for_voltage(VOUT_PIN, VOUT_NOM * 0.1, 10e-3);
    double t_off = Timer_Elapsed();

    if (t_off > T_OFF_MAX)
        TestResult_Fail("TURN_OFF_DELAY_FAIL", t_off);

    // Step 4: EN 低电平时的关机电流
    DPS_SelectCurrentRange(10e-6);
    DPS_MeasureCurrent(VIN_PIN, out i_shutdown);
    if (i_shutdown > I_SD_MAX)
        TestResult_Fail("SD_CURRENT_FAIL", i_shutdown);

    TestResult_Pass();
}
```

### 13.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| EN 高电平 (VIH) | VDD_IO × 0.7 ~ VDD_IO | 使能阈值 |
| EN 低电平 (VIL) | 0V ~ VDD_IO × 0.3 | 关断阈值 |
| EN 上拉/下拉 | 100kΩ (内部) | 通常内部有弱下拉 |
| 使能延迟 (t_ON) | 100µs ~ 2ms | 取决于稳压器类型 |
| 关断延迟 (t_OFF) | 100µs ~ 5ms | 取决于放电时间 |
| 温度 | 25°C | — |

### 13.5 判定标准

| 参数 | 最小 | 最大 | 单位 |
|------|------|------|------|
| EN 高电平阈值 | VDD_IO × 0.7 | — | V |
| EN 低电平阈值 | — | VDD_IO × 0.3 | V |
| 使能延迟 (t_ON) | — | 2000 | µs |
| 关断延迟 (t_OFF) | — | 5000 | µs |
| 关机电流 (EN=Low) | — | 1 | µA |

### 13.6 注意事项

1. **去抖滤波**：EN 管脚通常有去抖滤波（Debounce），快速翻转 EN 可能被忽略。脉冲宽度应大于去抖时间（通常 > 10µs）。
2. **上电序列**：如果 EN 控制多个电源轨，各电源轨的启动顺序和延迟时间需要分别测量。
3. **输入电平兼容性**：确保 EN 管脚的 VIH/VIL 阈值与测试系统的数字通道电平兼容。
4. **浮空状态**：如果 EN 浮空，内部弱下拉应确保芯片处于关断状态。测试时需验证浮空行为。
5. **同步 vs 异步**：区分 EN 是同步控制（依赖时钟）还是异步控制（纯组合逻辑），这会影响响应时间。

## 14. VBUS SENSE 检测测试 (VBUS Sense Detection)

### 14.1 测试目的

VBUS SENSE 检测测试用于验证 PMIC 的 **VBUS 插入/移除检测**功能。VBUS 是 USB 接口的 5V 电源线，PMIC 通过 VBUS_SENSE 管脚检测 USB 连接状态，以便：

- 检测 USB 插入事件 → 唤醒系统 / 启动充电
- 检测 USB 移除事件 → 终止充电 / 切换供电路径
- 提供 VBUS 过压保护（防止 VBUS 超过安全电压）

### 14.2 测试原理

PMIC 内部包含 VBUS 检测比较器，阈值通常设定为：

- **VBUS 插入阈值 (V_BUS_IN)**：~4.0V ~ 4.4V（上升沿检测）
- **VBUS 移除阈值 (V_BUS_OUT)**：~3.6V ~ 4.0V（下降沿检测）
- **迟滞**：防止在阈值附近震荡

USB 规范要求 VBUS 范围为 4.75V ~ 5.25V（标准 USB），因此检测阈值应在此范围内可靠触发。

### 14.3 测试方法

#### 插入检测测试

1. DUT 正常工作，VBUS_SENSE = 0V（模拟 USB 未插入）
2. 缓慢升高 VBUS_SENSE 电压（如 100mV/s）
3. 检测 PMIC 的 VBUS 插入标志寄存器是否置位
4. 记录触发时的 VBUS 电压

#### 移除检测测试

1. DUT 正常工作，VBUS_SENSE = 5V（模拟 USB 已插入）
2. 缓慢降低 VBUS_SENSE 电压
3. 检测 VBUS 插入标志寄存器是否清零
4. 记录触发时的 VBUS 电压

#### ATE 测试伪代码示例

```csharp
// VBUS SENSE 检测测试
void VBUS_SENSE_Test()
{
    double  vbus_step = 0.02;      // 20mV 步进
    double  v_in_th = 0;           // 插入阈值
    double  v_out_th = 0;          // 移除阈值

    // === 插入检测 (上升沿) ===
    DPS_ForceVoltage(VBUS_PIN, 0.0);
    wait(2e-3);

    for (double v = 0; v <= 6.0; v += vbus_step)
    {
        DPS_ForceVoltage(VBUS_PIN, v);
        wait(200e-6);

        uint8_t status = SPI_Read(REG_VBUS_STATUS);
        if (status & VBUS_PRESENT_MASK)
        {
            v_in_th = v;
            break;
        }
    }

    // === 移除检测 (下降沿) ===
    for (double v = 6.0; v >= 0; v -= vbus_step)
    {
        DPS_ForceVoltage(VBUS_PIN, v);
        wait(200e-6);

        uint8_t status = SPI_Read(REG_VBUS_STATUS);
        if (!(status & VBUS_PRESENT_MASK))
        {
            v_out_th = v;
            break;
        }
    }

    // 判定
    double hysteresis = v_in_th - v_out_th;
    if (v_in_th >= V_BUS_IN_MIN && v_in_th <= V_BUS_IN_MAX &&
        v_out_th >= V_BUS_OUT_MIN && v_out_th <= V_BUS_OUT_MAX &&
        hysteresis >= HYST_MIN)
        TestResult_Pass();
    else
        TestResult_Fail("VBUS_SENSE_FAIL", v_in_th, v_out_th);
}
```

### 14.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| VBUS 插入阈值 (V_BUS_IN) | 3.8V ~ 4.5V | USB 连接检测 |
| VBUS 移除阈值 (V_BUS_OUT) | 3.4V ~ 4.1V | 应低于插入阈值 |
| 迟滞 | > 200mV | 防震荡 |
| VBUS 最高承受电压 | 20V ~ 28V | 含 OVP 功能的设计 |
| 扫描步进 | 10mV ~ 50mV | 精度与时间折中 |
| 温度 | 25°C / 85°C | — |

### 14.5 判定标准

| 参数 | 最小值 | 典型值 | 最大值 | 单位 |
|------|-------|--------|-------|------|
| VBUS 插入阈值 (V_BUS_IN) | 3.8 | 4.1 | 4.5 | V |
| VBUS 移除阈值 (V_BUS_OUT) | 3.4 | 3.7 | 4.1 | V |
| 迟滞 | 200 | 400 | 700 | mV |

### 14.6 注意事项

1. **VBUS OVP 测试**：如果 PMIC 集成 VBUS OVP（过压保护），需要额外测试 VBUS OVP 阈值（通常 5.8V ~ 6.5V）。
2. **VBUS 快速插入**：实际应用中 VBUS 可能通过 USB 连接器快速插入（电压瞬变沿可能很陡）。ATE 的慢速扫描只能验证 DC 阈值，在系统级测试（SLT）中应补充验证快速插入场景。
3. **CDP/SDP/DCP 识别**：部分 PMIC 集成了 USB BC1.2 检测器，可以根据 VBUS 上的握手信号区分充电端口类型（标准下行端口 SDP、充电下行端口 CDP、专用充电端口 DCP）。如果芯片有此功能，需要额外的协议测试。
4. **VBUS 到 BAT 路径**：在检测到 VBUS 插入后，PMIC 通常会打开从 VBUS 到 BAT 的充电路径。测试时需注意 VBUS 电源的电流能力，防止过流。
5. **中断验证**：VBUS 插入/移除事件通常会产生中断信号（通过 FAULT_N 或专用中断管脚），需要与「FAULT_N 上报/响应测试」配合验证。

## 15. 四角 non-wetting 测试 (Corner Non-Wetting Test)

### 15.1 测试目的

四角 non-wetting 测试用于检测封装焊接过程中可能出现的**焊点不良 (Solder Joint Defect)**，特别是 QFN/BGA 封装**四角焊球的 non-wetting（不润湿）缺陷**。这种缺陷表现为：

- 焊球与 PCB 焊盘之间未形成良好的金属间化合物 (IMC)
- 焊点呈现"假焊"状态 — 物理接触但电气连接不良
- 在温度循环或机械应力下可能间歇性开路

### 15.2 测试原理

Non-wetting 缺陷的物理原理：

- **焊接过程**：焊料在加热后熔化，润湿焊盘表面，形成 Cu₆Sn₅ / Ni₃Sn₄ 等金属间化合物
- **Non-wetting**：由于焊盘氧化、污染、温度不足等原因，焊料未能与焊盘形成 IMC，仅靠机械压力接触
- **应力放大**：芯片四角在封装回流焊 (Reflow) 过程中承受最大的热-机械应力，因此 non-wetting 缺陷最可能出现在**四角管脚**

Non-wetting 缺陷的电气特征：

- 室温下可能表现正常（机械接触提供低阻路径）
- 温度变化时接触电阻发生显著变化（热胀冷缩）
- 大电流下接触点发热导致电阻进一步增大（正反馈）

### 15.3 测试方法

#### 方法一：温度循环 + 连续性监测 (最可靠)

1. 将 DUT 置于温度试验箱中
2. 执行温度循环：-40°C → +125°C → -40°C
3. 在每个温度点测量各管脚的接触电阻（使用 4-wire Kelvin 测量）
4. 分析电阻随温度的变化趋势

#### 方法二：大电流应力测试

1. 对可疑管脚施加短时大电流脉冲（如 100mA ~ 500mA）
2. 测量该管脚的电压降
3. Non-wetting 的管脚在电流应力下会表现出电阻跳变或持续增大

#### 方法三：OS 测试对比法 (FT 中最常用)

在 FT 中，对四角管脚进行**加严的 OS 测试**：

- 使用标准 OS 测试 + 额外的**温度应力**（热板 / 冷板）
- 在高温和低温下各做一次 OS 测试
- 比较两次 OS 测试的二极管压降差异，差异过大则判定为非润湿

#### ATE 测试伪代码示例

```csharp
// 四角 Non-Wetting 筛选测试 (FT 方法)
void Corner_NonWetting_Screening()
{
    // 对四角管脚 (物理上位于封装四角的管脚)
    Pin[] corner_pins = { PIN_A1, PIN_A2, PIN_B1, PIN_B2, ... };
    double  I_os = 500e-6;         // 500µA OS 测试电流
    double  delta_v_limit = 0.05;  // 允许的 5% 偏差
    double  vf_25[ ], vf_125[ ];   // 存储结果

    // 常温 (25°C) OS 测试
    for each (pin in corner_pins)
    {
        PPMU_ForceCurrent(pin, I_os);
        PPMU_MeasureVoltage(pin, out vf_25[pin]);
    }

    // 高温 (125°C) OS 测试 — 使用热板或温箱
    Thermal_Chamber_SetTemp(125);
    wait(30e-3);    // 等待热稳定

    for each (pin in corner_pins)
    {
        PPMU_ForceCurrent(pin, I_os);
        PPMU_MeasureVoltage(pin, out vf_125[pin]);
    }

    // 分析: 二极管压降的温度系数约为 -2mV/°C
    // 从 25°C 到 125°C, 正常 VF 应下降约 200mV
    // 如果某个管脚的 VF 变化偏离其他管脚 > 5%, 判定为 Non-Wetting
    for each (pin in corner_pins)
    {
        double delta_v = abs(vf_25[pin] - vf_125[pin]);
        double avg_delta = average(corner_pins, delta_v);

        if (abs(delta_v - avg_delta) / avg_delta > 0.05)
            TestResult_Fail(pin, "NON_WETTING_SUSPECT", delta_v);
    }

    Thermal_Chamber_SetTemp(25);    // 恢复常温
}
```

### 15.4 测试条件

| 参数 | 规格 | 说明 |
|------|------|------|
| 温度循环范围 | -40°C ~ +125°C | 工业级温度范围 |
| 循环次数 | 1 ~ 3 次 (FT) 或 500 ~ 1000 次 (可靠性验证) | FT 中受限于测试时间 |
| OS 测试电流 | 500µA ~ 1mA | 常规 OS 电流 |
| 阈值偏差 | ±5% ~ ±10% | 四角管脚之间的 VF 一致性 |
| 热稳定时间 | 10ms ~ 30ms | 等待温度均衡 |

### 15.5 判定标准

| 判定指标 | 正常 | Non-Wetting 嫌疑 | 说明 |
|---------|------|-----------------|------|
| VF 温度变化量 (25°C → 125°C) | 约 -200mV | 偏离平均值 > 5% | 二极管温度特性 |
| 四角 VF 一致性 | VF_max - VF_min < 20mV | VF_max - VF_min > 50mV | 同温度下 |
| 接触电阻 (4-wire) | < 1Ω | > 5Ω 或跳变 | 大电流测试 |

### 15.6 注意事项

1. **FT 中的局限性**：纯电学方法对 non-wetting 的检测灵敏度有限。如果 FT 中无法施加温度应力，可以考虑将此项测试移至**可靠性监控测试**（定期抽检）。
2. **四角选择**：不同的封装（QFN、BGA、CSP）四角管脚不同，需要根据封装图纸确定哪些管脚属于"四角"。
3. **机械应力模拟**：如果需要更高的检测覆盖率，可以在测试座（Socket）上增加额外的机械按压机构（如压棒），在测量时对芯片施加局部应力。
4. **区分 genuine non-wetting vs 封装应力**：封装应力也可能导致管脚电气特性变化，需要结合失效分析（FA）结果确认。
5. **Golden Unit 基准**：使用已知良好的 Golden Unit 建立四角管脚的 VF 温度特性基线，作为判据参考。
6. **与 X-ray 关联**：定期将电学判定的 Non-Wetting 嫌疑芯片送 X-ray 检测，以验证判定标准有效性。
